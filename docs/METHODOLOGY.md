# Methodology

## 1. Destination profile
A destination-level table combines structural and tourism attributes. Direct demand fields are retained for interpretation but are excluded from the clustering feature matrix.

## 2. Undermeasured candidates
Destinations without direct demand series in the current project are marked as undermeasured rather than assumed unpopular.

## 3. Clustering
The runnable clustering script uses:
- log-transformed structural count/economic features;
- standardized numerical features;
- binary tourism-theme features;
- one-hot tourism region;
- K-Means diagnostics from k=2 to k=18.

It exports diagnostics plus k=15 and k=17 memberships. These are analytical partitions; territorial feasibility remains a separate question.

## 4. Product association mining
Each official tourism product is treated as one transaction containing its municipalities. The script calculates support, confidence and lift for directional municipality pairs.

These rules describe how destinations are packaged in the sampled tourism offer. They do not represent visitor behavior.

## 5. Territorial and ML results
The repository retains the current territorial shortlist and prior regression evaluation as result artifacts. Their larger source histories are external and therefore are not regenerated by the small local pipeline.
